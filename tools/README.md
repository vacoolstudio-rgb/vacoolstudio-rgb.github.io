# Как собирается этот сайт

```
python3 tools/build_site.py          # собрать
python3 tools/build_site.py --check  # проверить, что собранное совпадает с данными
```

`tools/site_data.py` — единственное место, где живёт содержимое.
`tools/build_site.py` — разметка. Всё остальное в корне репозитория —
результат сборки, и править его руками бессмысленно: следующий запуск перезапишет.

Исключение — `privacy/index.html`. Это юридический текст, он написан отдельно и
генератором не трогается.

## Что уже сделано для индексации

**Отдельный адрес на приложение** — `/cycle/`, `/screen/`, `/budget/`, `/reader/`,
`/media/`, `/subs/`, `/kitchen/`. Одна страница со списком из семи не могла
ранжироваться ни по одному конкретному запросу: у неё один `<title>` и текст,
размазанный между «трекером цикла» и «конвертером видео».

**Заголовок и описание заданы вручную** в `seo_title` / `seo_description`, а не
собраны из tagline. Google обрезает заголовок примерно на 60 знаках, описание —
на 155; обрезанное предложение читается как сломанное. Длину и уникальность
стережёт `check_seo()` в генераторе: два приложения с одинаковым заголовком
соревнуются друг с другом за один запрос, и выигрывает случайное.

**Разметка Schema.org** на каждой странице: `SoftwareApplication` (карточка
приложения), `FAQPage` (раскрывающиеся вопросы прямо в выдаче), `BreadcrumbList`
(путь вместо голого адреса). Рейтинга и числа отзывов там нет намеренно — Google
требует, чтобы такие поля отражали видимое на странице, а выдуманный рейтинг
приводит к снятию всей разметки.

**`sitemap.xml` и `robots.txt`** — собираются вместе со страницами, так что новое
приложение попадает в карту сайта само.

**`<meta name="keywords">` не выводится.** Google не читает его с 2009 года, а
перечисление ключей в коде — сигнал спама. Слова стоят там, где их взвешивают: в
заголовке, первом абзаце и подзаголовках.

## Новое приложение

Страница появляется, когда приложение **вышло** хотя бы в один магазин. Порядок:

1. дописать блок в `site_data.py` — slug, названия, `seo_title`/`seo_description`,
   идентификаторы магазинов, вступление, разделы, вопросы;
2. положить иконку в `icons/`;
3. `python3 tools/build_site.py` — страница, ссылка с главной, карта сайта и
   перелинковка соберутся сами;
4. `python3 tools/ping_indexnow.py` — Bing и Yandex узнают сразу.

Приложение без идентификаторов магазинов считается невышедшим: `is_released()`
вычисляет это из самих идентификаторов, а не из отдельного флага — два поля об
одном и том же однажды разойдутся молча. Такое приложение попадает одной строкой
в раздел «In the works» на главной и **не получает собственного адреса**.

Так сделано не из аккуратности. Странице невышедшего приложения нечего сказать —
ни ссылки, ни того, как оно работает. Google называет это «тонким контентом» и
оценивает по нему сайт целиком, а не только эту страницу. И хуже: заглушка
успевает попасть в индекс как обещание, а это состояние держится в выдаче ещё
недели после того, как приложение вышло.

## Ключевые слова

Поле `queries` у каждого приложения — это запросы, под которые написан текст. Оно
не попадает в разметку; оно существует, чтобы при правке было видно, что нельзя
потерять. Проверять формулировки стоит против трёх вещей:

- **Категория** — то, как человек называет саму задачу: `period tracker app`,
  `tv show tracker`, `expense tracker`, `ebook reader`.
- **Отличие** — то, ради чего выбирают именно это: `no account`, `offline`,
  `without bank login`, `no subscription`, `private`.
- **Повод** — событие, из-за которого ищут сегодня. Самый ценный из них у нас
  сейчас: **`TV Time alternative`** — сервис закрылся 15 июля 2026, и люди до сих
  пор ищут, куда перенести историю. Eluna Screen импортирует их экспорт с
  исходными датами просмотра, и это ровно то, чего у большинства замен нет.

Категория даёт объём, отличие — конверсию, повод — трафик здесь и сейчас.

## Уведомить поисковики о новых страницах

```
python3 tools/ping_indexnow.py            # все адреса из sitemap.xml
python3 tools/ping_indexnow.py /screen/   # только эти
```

Это Bing (а с ним DuckDuckGo, Yahoo, Ecosia) и Yandex. **Google так уведомить
нельзя**: его Indexing API открыт только для вакансий и трансляций, для
остальных страниц его использование прямо запрещено правилами. Туда — только
Search Console и sitemap.

Ответ 202 значит «принято», а не «проиндексировано»: индексация остаётся
решением поисковика и на молодом домене занимает дни или недели.

## Что осталось сделать по индексации

1. **Search Console** — единственный обязательный ручной шаг. Подтвердить домен
   `eluna-apps.com`, отправить `https://eluna-apps.com/sitemap.xml`, запросить
   индексацию семи новых адресов. Без этого Google найдёт их сам, но не скоро.
2. **Bing Webmaster Tools** — уведомления уже уходят, но панель показывает
   ошибки обхода и запросы, по которым сайт показывают.
3. **Проверить разметку** в Rich Results Test на паре адресов после выкладки.
4. **Ссылки со стороны.** Домен молодой, и без внешних ссылок он будет расти
   медленно. Самое дешёвое и честное: адрес приложения в поле «Support URL» и
   «Marketing URL» карточки App Store и Play — они индексируются и ведут на нас.

## Как будет устроена локализация

Каркас уже стоит, и это не обещание, а три конкретные вещи в коде:

- `LOCALES` в `build_site.py` — список языков. Сейчас `['en']`. Первый в списке
  живёт в корне, остальные получают префикс: `/ru/screen/`.
- `path_for()` уже строит адреса с учётом языка, а `head()` уже выводит
  `hreflang` для каждого языка из списка плюс `x-default`. То есть при добавлении
  языка перелинковка проставится сама — а забытый `hreflang` это ровно тот
  дефект, который потом ищут неделями.
- `sitemap()` перечисляет то, что реально собрано, поэтому новые адреса попадут
  в карту без отдельной правки.

Чего ещё нет и что нужно будет сделать:

1. **Разложить тексты по языкам.** Сейчас поля в `site_data.py` — строки.
   Станут словарями `{'en': …, 'ru': …}`, либо появится отдельный файл на язык.
   Второе лучше: переводчику удобнее один файл, а diff читаемее.
2. **Взять переводы, а не заказывать заново.** Описания приложений уже переведены
   на 61 язык в `fastlane/metadata/android/<locale>/` каждого приложения — там
   выверенный текст, который прошёл через магазины. Оттуда же брались тексты для
   английских страниц, так что структура совпадает.
3. **Переключатель языка** в шапке и `<html lang>` по локали.
4. **Решить, сколько языков.** Не все 61: страница на языке, на котором никто не
   ищет эти приложения, — это работа впустую и лишние адреса в индексе. Разумный
   первый круг — языки, где у приложений уже есть установки.
